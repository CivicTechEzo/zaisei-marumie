# フェーズ2-2: 用語の平易化設計

## 目的

**住民が**、自治体財政の専門用語（地方交付税、扶助費、公債費等）に馴染みがなく、ダッシュボードを見ても「何のことかわからない」と感じる状態を解消するため。

正式名称の代わりに日常的な言葉（例: 地方交付税 → 国からの仕送り）をデフォルトで表示し、正式名称はカッコ書きで併記する。

---

## 前提条件

- フェーズ2-1（loader/usecase差し替え）が完了し、サンキー図が新データモデルで動作している状態
- タブは「目的別」「性質別」の2つ（フェーズ2-1で変更済み）

---

## 適用方式

**デフォルト平易表現 + 正式名称カッコ書き**

サンキー図のノードラベルをデフォルトで平易な表現にし、正式名称をカッコ書きで併記する。ユーザーが切り替える必要はなく、常に両方の情報が見える状態にする。

理由:
- タブが増えると選択の認知コストが上がり、「見るハードルを下げる」に反する
- 正式名称も併記することで、自治体職員や詳しい住民にも違和感がない
- ツールチップはモバイルで使いにくいため、カッコ書きのほうがアクセシブル

## 1. 用語マッピングの定義

### 配置方針

用語マッピングは `shared/accounting/account-category.ts` の `FiscalCategory` に `friendlyLabel` フィールドを追加する形で統合する。

理由:
- 科目定義と平易表現の対応を1箇所で管理できる
- フィールド名 → 正式名称 → 平易表現 の対応が型安全に保証される
- 別ファイル（`friendly-term-map.ts`）にすると、科目追加時の更新漏れリスクがある

### FiscalCategory への friendlyLabel 追加

`shared/accounting/account-category.ts` の `FiscalCategory` interface を拡張:

| フィールド | 説明 |
|-----------|------|
| `friendlyLabel` | 平易な表現。正式名称と同じ場合は省略可（optional） |

`friendlyLabel` が未定義の場合は `label`（正式名称）をそのまま使用する。

## 2. SankeyChart.tsx のラベル表示変更

### 変更方針

SankeyChart のカスタムラベルレイヤー（`CustomLabelsLayer`）で、ノードラベルの表示を変更する。

**表示形式**:

```
国からの仕送り
（地方交付税）
52億3,000万円
```

1行目: 平易な表現（`friendlyLabel`）
2行目: 正式名称をカッコ書き（`label`）— friendlyLabel と label が同じ場合は省略
3行目: 金額

### ラベル解決ロジック

SankeyChart はノードの `label` フィールド（文字列）を受け取って描画する。現在のパイプラインでは `FiscalCategory.label` がそのまま SankeyNode の `label` になる。

**方針**: SankeyNode の `label` を変更するのではなく、表示時に解決する。

1. `shared/accounting/account-category.ts` から `FISCAL_CATEGORY_BY_FIELD` を使わず、`label` をキーとした逆引き辞書を作成:
   - `FRIENDLY_LABEL_MAP: Record<string, string>` — 正式名称 → 平易表現のマッピング
   - `ALL_FISCAL_CATEGORIES` から `friendlyLabel` が定義されている項目のみ抽出して構築

2. SankeyChart のラベル描画時に `FRIENDLY_LABEL_MAP[node.label]` で平易表現を取得
   - 存在すれば: 1行目に平易表現、2行目にカッコ書きで正式名称
   - 存在しなければ: 現在通り正式名称のみ

**配置**: `FRIENDLY_LABEL_MAP` は `shared/accounting/account-category.ts` にユーティリティとして追加する。クライアントから参照されるため `server-only` は含めない（account-category.ts は現在もクライアントから参照可能）。

### SankeyChart のレイアウト調整

ラベルが2行になることで、ノードの高さやレイアウトに影響する可能性がある:
- フォントサイズ: 平易表現は現在と同じサイズ、正式名称は小さめ（`text-xs` or `0.7em`）
- 行間: コンパクトに保つ（`leading-tight`）
- ノード幅が狭い場合: カッコ書きは省略し平易表現のみ表示（レスポンシブ対応）

## 3. FinancialSummarySection.tsx の変更

FinancialSummarySection はフェーズ2-1で「歳入総額」「歳出総額」「実質収支」の3カードに変更される。カードのタイトルは固定文言のため、用語の平易化の対象外。

ただし、将来的にカテゴリ別の内訳表示（「最も多い歳出: 福祉・医療」など）を追加する場合は `FRIENDLY_LABEL_MAP` を適用する。フェーズ2-3（ひとことサマリー）での利用を想定。

## 4. CashFlowSection.tsx の見出し変更

| 項目 | 変更前（フェーズ2-1完了時） | 変更後 |
|------|--------------------------|--------|
| CardHeader title | 「収支の流れ」 | 「お金の流れ」 |
| CardHeader subtitle | 「どこからお金を得て、何に使っているか」 | （そのまま） |
| タブラベル | 「目的別」「性質別」 | 「なにに使った？（目的別）」「どう使った？（性質別）」 |

タブラベルの変更理由: 「目的別」「性質別」は財政用語であり、住民には違いがわかりにくい。疑問文形式にすることで、各タブが何を示すかを直感的に伝える。
