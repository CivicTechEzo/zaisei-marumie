# フェーズ2-1: loader/usecase差し替え設計

## 目的

**住民が**、自分のまちの財政データ（歳入・歳出のサンキー図、財務サマリー）をダッシュボードで閲覧できない状態を解消するため。

現在のwebappは旧プロジェクト（政治資金可視化）の表示ロジック（Transaction, PoliticalOrganization）のままで、新データモデル（Municipality, FiscalYearSettlement）に接続されていない。本設計では、データの入口（loader/usecase/repository）を新データモデルに差し替え、UIコンポーネント（SankeyChart, FinancialSummarySection等）を新しいデータ構造に対応させる。

---

## 前提条件

- 旧コード削除（`20260414_0645_旧コード削除と流用コード書き換え設計.md` の Step 1-2）が完了していること
- FiscalYearSettlement テーブルにはデータ未投入のため、開発用シードデータを用意する

---

## 変更の全体像

```
現在:
  page.tsx → loadTopPageData → usecase群 → repository群 → Transaction / PoliticalOrganization
                                                           (Prismaモデル消失でエラー)

変更後:
  page.tsx → loadTopPageData → GetSankeyAggregationUsecase → IMunicipalityRepository
                                                           → IFiscalSettlementRepository
                                                           → FiscalSettlementToAggregationService

```

**必要なクエリ**:

| メソッド | 引数 | 戻り値 | 用途 |
|---------|------|--------|------|

**FiscalYearSettlement ドメインモデル**:

`webapp/src/server/contexts/public-finance/domain/models/fiscal-year-settlement.ts` に定義する。

**金額の単位方針**:
- FiscalYearSettlement のDB値は千円単位（決算カードの原典に準拠）
- ドメインモデルでも千円単位のまま保持する（変換で精度が落ちるリスクを回避）
- UI表示時に `formatAmount` で万円・億円に変換する
- `formatAmount` を千円単位入力に対応させる（後述 #17）

### 1-4. PrismaFiscalSettlementRepository

**配置**: `webapp/src/server/contexts/public-finance/infrastructure/repositories/prisma-fiscal-settlement.repository.ts`

- Decimal フィールド（財政指標）は `parseFloat()` で変換

## 2. 新規ドメインサービスの作成

### FiscalSettlementToAggregationService

**配置**: `webapp/src/server/contexts/public-finance/domain/services/fiscal-settlement-to-aggregation.service.ts`

**責務**: FiscalYearSettlement のフィールド値を `REVENUE_CATEGORIES` / `EXPENSE_PURPOSE_CATEGORIES` / `EXPENSE_NATURE_CATEGORIES` とマッピングし、CategoryAggregation を構築する。

**判断**: 複数エンティティ（FiscalYearSettlement と FiscalCategory定義）にまたがるマッピングロジックのため、Domain Service として実装する。

**インターフェース**:

| メソッド | 引数 | 戻り値 |
|---------|------|--------|
| `toAggregation` | `settlement: FiscalYearSettlement, mode: "purpose" \| "nature"` | `CategoryAggregation` |

**変換ロジック**:

1. `REVENUE_CATEGORIES` の各項目について:
   - `settlement[fieldName]` の値を取得（number、千円単位）
   - 値が 0 の科目はスキップ（サンキー図のノイズ防止）
   - `CategoryAggregationItem` を生成: `{ category: category.label, totalAmount: value }`

2. `mode` に応じて `EXPENSE_PURPOSE_CATEGORIES` または `EXPENSE_NATURE_CATEGORIES` を使用し、同様に変換

3. 歳入・歳出の合計値の整合性チェック:
   - 歳入: 内訳合計と `settlement.revTotal` を比較（不一致時は warning ログ）
   - 歳出: 内訳合計と `settlement.expPurposeTotal` or `settlement.expNatureTotal` を比較

**サブカテゴリについて**:

決算カードは款レベルの集計値であり、旧Transaction モデルのようなサブカテゴリ構造がない。そのため、初期実装ではサブカテゴリは使用しない。将来的に節レベルのデータを追加する場合に拡張可能な設計とする（CategoryAggregationItem の `subcategory` フィールドは残す）。

## 3. category-aggregation.ts の修正

### BalanceInfo の簡略化

**現在の BalanceInfo**:

| フィールド | 用途 |
|-----------|------|
| `previousYearBalance` | 前年度末の現金残高（旧 BalanceSnapshot） |
| `currentYearBalance` | 当年度末の現金残高（同上） |
| `liabilityBalance` | 負債残高（旧 BalanceSheet） |

**変更後**:

自治体財政データでは、旧プロジェクトの「現金残高」「未払費用」概念が存在しない。歳入には繰越金（`revCarryover`）が既に含まれており、歳入合計 - 歳出合計 = 実質収支となる。

`adjustWithBalance` メソッドは不要になる。歳入と歳出の差額は SankeyDataBuilder 内の既存ロジック（差額を「(仕訳中)」ノードとして追加）で処理される。

**変更内容**:
- `BalanceInfo` interface を削除
- `adjustWithBalance` メソッドを削除
- 呼び出し元（GetSankeyAggregationUsecase）から `adjustWithBalance` の呼び出しを削除

`renameOtherCategories` と `consolidateSmallItems` はそのまま維持する（歳入・歳出に「その他」カテゴリが存在するため）。

## 4. GetSankeyAggregationUsecase の書き換え

**配置**: `webapp/src/server/contexts/public-finance/application/usecases/get-sankey-aggregation-usecase.ts`

### 依存の変更

| 現在 | 変更後 |
|------|--------|
| `ITransactionRepository` | 削除 |
| `IPoliticalOrganizationRepository` | `IMunicipalityRepository` |
| `IBalanceSnapshotRepository` | 削除 |
| `IBalanceSheetRepository` | 削除 |
| — | `IFiscalSettlementRepository`（追加） |

### パラメータの変更

| 現在 | 変更後 |
|------|--------|
| `slugs: string[]` | `slug: string`（単一自治体に変更） |
| `financialYear: number` | `fiscalYear: number` |
| `categoryType: "political-category" \| "friendly-category"` | `expenseMode: "purpose" \| "nature"` |

slug を単一に変更する理由: 自治体財政データは自治体単位の年度集計であり、複数自治体の合算表示はユースケースとして不要。

### 処理フローの変更

```
1. IMunicipalityRepository.findBySlug(slug) で Municipality を取得
2. IFiscalSettlementRepository.findByMunicipalityAndYear(municipalityId, fiscalYear) で決算データ取得
3. FiscalSettlementToAggregationService.toAggregation(settlement, expenseMode) で CategoryAggregation を構築
4. CategoryAggregation.renameOtherCategories() で「その他」をリネーム
5. SankeyDataBuilder.build(aggregation) で SankeyData を構築
```

旧コードとの主な違い:
- Transaction の集計処理が不要（FiscalYearSettlement が集計済み）
- BalanceSnapshot/BalanceSheet の取得が不要
- `adjustWithBalance` の呼び出しが不要
- `consolidateSmallItems` はサブカテゴリがない初期実装では不要だが、呼び出し自体は残す（サブカテゴリがなければ何もしない）

## 8. financial-calculator.ts の修正

### formatAmount の千円単位対応

FiscalYearSettlement の金額は千円単位。現在の `formatAmount` は円単位を想定しているため、千円単位入力に対応させる。

**方針**: `formatAmount` に `unit` オプションを追加するのではなく、呼び出し側で千円→円に変換してから渡す。

理由: `formatAmount` は SankeyData 経由でも呼ばれるため、入力単位が混在すると複雑になる。

具体的には:
- FiscalSettlementToAggregationService で CategoryAggregation を構築する際、千円 → 円の変換を行う（`value * 1000`）
- 以降のパイプライン（SankeyDataBuilder, FinancialSummarySection）は円単位で統一
- `formatAmount` は変更不要
