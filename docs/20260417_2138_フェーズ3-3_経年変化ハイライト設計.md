# フェーズ3-3: 経年変化ハイライト 設計

## 目的

**住民が**、自分のまちの財政が「去年と比べてどう変わったか」を一目で把握できるようにするため。

サンキー図やサマリーは単年度のスナップショットであり、「何が増えた／減った」「まちの財政はどっちに向かっているのか」がわからない。前年度との比較で大きく変化した項目を自動検出しハイライト表示することで、住民が自治体の動向をつかめるようにする。

---

## スコープ

表示年度と前年度のデータを比較し、金額の変化が大きい項目を自動検出して一覧表示する。

### 検出対象

| 区分 | 対象フィールド | 件数 |
|------|---------------|------|
| 歳入カテゴリ | `REVENUE_CATEGORIES` の全 fieldName | 24 |
| 歳出・目的別カテゴリ | `EXPENSE_PURPOSE_CATEGORIES` の全 fieldName | 13 |
| 歳出・性質別カテゴリ | `EXPENSE_NATURE_CATEGORIES` の全 fieldName | 13 |
| 合計 | `revTotal`, `expPurposeTotal`, `expNatureTotal` | 3 |
| ストック | `reserveFundTotal`, `localBondBalance` | 2 |

計55項目から変化量を計算し、上位を抽出する。

### 検出対象外

財政指標（`fiscalPowerIndex`, `currentBalanceRatio` 等）は比率・指数であり、「○千円増えた」と同列に扱えないため対象外とする。これらは3-1の指標コンポーネントで経年変化を表示する。

---

## 検出アルゴリズム

### 変化量の計算

各項目について以下を算出する:

- **絶対変化量**: `current - previous`（千円）
- **変化率**: `(current - previous) / previous × 100`（%）

### フィルタリング

以下の条件をすべて満たす項目のみ抽出対象とする:

1. **最小金額フィルタ**: 当年度・前年度のいずれかの金額が、当年度歳出総額の 0.5% 以上であること
   - 理由: 元が極小の項目は変化率が大きくても住民への影響が小さい
   - 例: 歳出100億円の自治体なら、5,000万円以上の項目のみ対象
2. **ゼロ除算回避**: 前年度の値が 0 の場合は変化率を算出せず、絶対変化量のみで評価する

### ランキング

- 絶対変化量の大きさ（`|absoluteChange|`）で降順ソート
- **上位5件**を抽出する
- 増加・減少の混在を許容する（「増えたもの」「減ったもの」を分けない）

絶対変化量でランキングする理由: 住民にとっての影響度は「何%変わったか」より「何円変わったか」のほうが直感的。変化率はサブ情報として併記する。

## バックエンド設計

### ドメイン型

`domain/types/year-over-year-change.ts` に配置する。

**YearOverYearChange（1項目の変化）:**

```
interface YearOverYearChange {
  fieldName: string;            // FiscalYearSettlement のフィールド名
  label: string;                // 正式名称
  friendlyLabel: string;        // 平易な表現
  currentValue: number;         // 当年度の値（千円）
  previousValue: number;        // 前年度の値（千円）
  absoluteChange: number;       // 絶対変化量（千円）。正=増加、負=減少
  percentageChange: number | null; // 変化率（%）。前年度が0の場合はnull
  category: "revenue" | "expense-purpose" | "expense-nature" | "total" | "stock";
}
```

**YearOverYearHighlights（ハイライト全体）:**

```
interface YearOverYearHighlights {
  currentYear: number;
  previousYear: number;
  items: YearOverYearChange[];  // 上位5件、|absoluteChange|降順
}
```

### ドメインサービス

`domain/services/year-over-year-detector.ts` に配置する。

**責務:**

- 2つの `FiscalYearSettlement`（当年度・前年度）を受け取り、全55項目の変化量を計算する
- `account-category.ts` の定義を参照し、各 fieldName に対応する label / friendlyLabel を取得する
- 合計・ストック項目は定義が `account-category.ts` にないため、サービス内で定義する
- フィルタリングとランキングを適用し、`YearOverYearHighlights` を返す

**配置理由:**

- 複数フィールドにまたがる比較ロジック → Domain Service
- `account-category.ts` のカテゴリ定義を使ったラベル解決 → ドメイン知識

### ユースケース

`application/usecases/get-year-over-year-highlights-usecase.ts`

**処理フロー:**

1. `municipalityRepository.findBySlug(slug)` で自治体を取得
2. `fiscalSettlementRepository.findByMunicipalityAndYear(id, currentYear)` で当年度データを取得
3. `fiscalSettlementRepository.findByMunicipalityAndYear(id, currentYear - 1)` で前年度データを取得
4. 前年度データが存在しない場合は `null` を返す
5. ドメインサービスで変化量を検出
6. `YearOverYearHighlights` を返す

**注:** 3-1 で導入予定の `findAllByMunicipality` を使ってもよいが、3-3 は当年度と前年度の2年分のみ必要なため、既存の `findByMunicipalityAndYear` を2回呼ぶほうがシンプル。

### ローダー

`presentation/loaders/load-year-over-year-highlights.ts`

- `unstable_cache` でラップ
- キャッシュキー: `["year-over-year-highlights", slug, fiscalYear]`
- tags: `["year-over-year-highlights"]`
- revalidate: `CACHE_REVALIDATE_SECONDS`

## フロントエンド設計

### ダッシュボードへの配置

CashFlowSection の直前に配置する。歳入歳出の詳細を見る前に「今年はここが変わった」という文脈を先に伝える。

```
┌──────────────────────────────────────┐
│  PerCapitaToggle（3-2）              │
├──────────────────────────────────────┤
│  ★ YearOverYearSection ← NEW       │
├──────────────────────────────────────┤
│  CashFlowSection（既存）             │
│  ...                                 │
├──────────────────────────────────────┤
│  3-1 指標セクション群                 │
│  ...                                 │
```

**配置意図:**

- 「去年と比べて何が変わったか」はダッシュボード全体の文脈を設定する情報
- この文脈を持った上でサンキー図や指標を見ると、「なるほどここが増えたのか」と理解が深まる

### コンポーネント設計

#### YearOverYearSection

**表示イメージ:**

```
┌────────────────────────────────────────────────┐
│ 前年度からの変化（令和5年度 → 令和6年度）       │
│                                                │
│  ↑ 福祉・医療（民生費）  +3億2000万円（+8.5%） │
│  ↑ 自治体の借金（地方債）  +2億円（+12.3%）     │
│  ↓ 住民が納めた税金（地方税）-1億5000万円(-4.2%)│
│  ↑ 借金の返済（公債費）   +8000万円（+5.1%）    │
│  ↓ 道路・建物の工事       -7000万円（-15.2%）   │
│                                                │
└────────────────────────────────────────────────┘
```

- 各行: 方向アイコン（↑/↓）、平易な表現（正式名称）、絶対変化量、変化率
- 増加行: テキスト色に暖色系（`#DC2626` 等）のアクセント
- 減少行: テキスト色に寒色系（`#2563EB` 等）のアクセント
- 方向の色分けは価値判断（良い/悪い）ではなく、単純に増減の方向を示すもの

**Props:**

```
interface YearOverYearSectionProps {
  highlights: {
    currentYear: number;
    previousYear: number;
    items: Array<{
      friendlyLabel: string;
      label: string;
      absoluteChange: number;      // 千円
      percentageChange: number | null;
    }>;
  };
}
```

**実装方針:**

- サーバーコンポーネントとして実装可能（状態管理不要）
- CSS（Tailwind）のみで描画
- 金額フォーマットは既存の `formatAmount`（円単位）を使用。千円→円への変換はコンポーネント側で行う
- 年度ラベルは和暦（「令和○年度」）

### 1人あたりモード対応（3-2連携）

3-2 のトグルが有効な場合、変化量も1人あたりに換算する。

- `absoluteChange` を `population` で割る
- 表示: 「1人あたり +○万円（+8.5%）」
- 変化率は変わらない（分母分子を同じ population で割るため）
- PerCapitaContext から `isPerCapita` と `population` を読み取る
- この対応のため、サーバーコンポーネントではなくクライアントコンポーネントとする

## データフロー全体図

```
page.tsx
  └─ loadYearOverYearHighlights(slug, fiscalYear)
       └─ GetYearOverYearHighlightsUsecase
            ├─ municipalityRepository.findBySlug()
            ├─ fiscalSettlementRepository.findByMunicipalityAndYear(id, currentYear)
            └─ fiscalSettlementRepository.findByMunicipalityAndYear(id, currentYear - 1)
                 └─ YearOverYearDetector.detect(current, previous)
                      ├─ 55項目の変化量計算
                      ├─ フィルタリング（最小金額）
                      └─ ランキング（上位5件）
                           ↓
                      YearOverYearHighlights
                           ↓
  └─ YearOverYearSection ← highlights
```

---

## エッジケース

| ケース | 対応 |
|--------|------|
| 前年度データなし | セクション全体を非表示 |
| 変化がすべて0 | セクション全体を非表示 |
| フィルタ後の項目が5件未満 | あるだけ表示（1件でも表示） |
| フィルタ後の項目が0件 | セクション全体を非表示 |
| 前年度の値が0で当年度に新規発生 | 変化率は `null`（「新規」と表示）、絶対変化量でランキングに参加 |
