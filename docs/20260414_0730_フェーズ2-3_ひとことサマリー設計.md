# フェーズ2-3: ひとことサマリー設計

## 目的

**住民が**、数字の羅列やサンキー図を見る前に「なるほど」と思える要約がなく、財政データに取っ付きにくいと感じる状態を解消するため。

ダッシュボード上部に、自然言語で1〜2文の財政サマリーを表示し、「見てみよう」→「なるほど」の入口を作る。

## 1. テンプレート設計

### データソース

SankeyData（目的別）から以下の値を抽出する。FinancialSummarySection と同じ `createSankeyDataHelper` ロジックを流用する。

| 要素 | 取得方法 |
|------|---------|
| 歳出総額 | 「合計」ノードからの流出 - 「(仕訳中)」 |
| 歳入総額 | 「合計」ノードへの流入合計 |
| 最大歳出カテゴリ名 | 「合計」→ 各expenseノードのリンクのうち最大のもの（「(仕訳中)」除く） |
| 最大カテゴリの割合 | 最大カテゴリ金額 / 歳出総額 × 100 |
| 実質収支 | 歳入総額 - 歳出総額 |
| 自主財源比率 | 地方税 / 歳入総額 × 100（概算） |

最大歳出カテゴリ名は `FRIENDLY_LABEL_MAP` で平易表現に変換する（フェーズ2-2の成果を活用）。

### テンプレートパターン

テンプレートはデータの特徴に応じて出し分ける。優先度の高いパターンから順に判定し、最初にマッチしたものを使用する。

#### パターン1: カテゴリ偏り強調（最大カテゴリが40%超の場合）

```
{displayName}の{year}年度の支出は{expense}。
「{topCategory}」が全体の{percentage}%を占めています。
```

例: 「札幌市の2022年度の支出は約1兆880億円。「福祉・医療」が全体の45%を占めています。」

#### パターン2: 赤字強調（実質収支が負の場合）

```
{displayName}の{year}年度は、収入{income}に対し支出{expense}で、{deficit}の赤字です。
```

例: 「夕張市の2022年度は、収入約110億円に対し支出約115億円で、約5億円の赤字です。」

#### パターン3: 依存財源強調（自主財源比率が30%未満の場合）

```
{displayName}の{year}年度の収入は{income}。
うち住民の税金は{percentage}%で、残りは国や道からの交付金・補助金です。
```

例: 「東川町の2022年度の収入は約82億円。うち住民の税金は15%で、残りは国や道からの交付金・補助金です。」

#### パターン4: 基本パターン（上記に該当しない場合のフォールバック）

```
{displayName}の{year}年度の支出は{expense}。
最も多いのは「{topCategory}」（{percentage}%）です。
```

### 金額のフォーマット

テンプレート内の金額表示には「約」を付けて概算であることを示す:
- 1兆円以上: 「約X兆Y億円」（Y=0なら「約X兆円」）
- 1億円以上: 「約X億Y,000万円」→ 簡略化して「約X億円」
- 1億円未満: 「約X,000万円」

専用のフォーマット関数 `formatApproxAmount` を作成する（既存の `formatAmount` はカード表示用で形式が異なる）。

## 2. SummaryCard コンポーネント

### 配置

`webapp/src/client/components/top-page/SummaryCard.tsx`

### 設計方針

- サーバーコンポーネントではなくクライアントコンポーネントとして実装する
  - 理由: CashFlowSection 内に配置されるため（CashFlowSection は `"use client"`）
- SankeyData を props で受け取り、テンプレートロジックで文章を生成する
- LLM は使わない（テンプレートベース）

### Props

| prop | 型 | 説明 |
|------|-----|------|
| `sankeyData` | `SankeyData \| null` | 目的別のサンキーデータ |
| `displayName` | `string` | 自治体名 |
| `year` | `number` | 年度 |

### レイアウト

- CashFlowSection 内、FinancialSummarySection の直上に配置
- 背景色: 薄い緑系（`bg-emerald-50` or `bg-teal-50`）でサマリーであることを視覚的に区別
- パディング: `p-4`
- 角丸: `rounded-lg`
- テキスト: 本文は `text-sm` or `text-base`、数値部分は `font-bold`
- データがない場合（`sankeyData` が null）: コンポーネント自体を非表示

## 3. summary-template.ts（テンプレートエンジン）

### 配置

`webapp/src/client/lib/summary-template.ts`

### 責務

SankeyData + 自治体情報 + 年度 から、表示するサマリー文字列を生成する。

### インターフェース

```
generateSummary(params: SummaryParams): string | null

SummaryParams:
  sankeyData: SankeyData
  displayName: string
  year: number
```

戻り値が `null` の場合: データ不足で文章を生成できない（SummaryCard は非表示）。

### 内部ロジック

1. SankeyData からメトリクスを抽出（歳入総額、歳出総額、最大カテゴリ等）
2. メトリクスに基づいてテンプレートパターンを選択（パターン1→2→3→4の優先順）
3. テンプレートに値を埋め込んで文字列を返す

### メトリクス抽出の共通化

FinancialSummarySection と SummaryCard の両方で SankeyData からメトリクスを抽出する処理がある。重複を避けるため、メトリクス抽出ロジックを共通関数として切り出す。

**配置**: `webapp/src/client/lib/sankey-metrics.ts`

```
extractSankeyMetrics(sankeyData: SankeyData): SankeyMetrics

SankeyMetrics:
  income: number         // 歳入総額
  expense: number        // 歳出総額
  balance: number        // 実質収支
  topExpenseCategory: string   // 最大歳出カテゴリ名
  topExpenseAmount: number     // 最大歳出カテゴリ金額
  topExpensePercentage: number // 最大歳出カテゴリの割合（%）
  localTaxAmount: number       // 地方税額（自主財源比率計算用）
  localTaxPercentage: number   // 自主財源比率（%）
```

FinancialSummarySection の `calculateFinancialData` / `calculateBalanceDetailData` もこの共通関数を使うようにリファクタリングする。
